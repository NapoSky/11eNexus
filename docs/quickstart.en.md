# 11eNexus

11eNexus keeps active game channels visible, archives inactive games without deleting their history, and lets members manage optional game notifications. The public panel is bilingual; personal menus and modals follow each member’s Discord language (French or English).

**Games** opens active games; **Archives** opens archived games even though their channels are hidden. The personal catalogue shows the full catalogue count and the active/archived counts. Its filter also offers all games. A list of fifteen active games does not mean only fifteen were imported.

The public panel and private pages use **Components V2**, with short explanations next to the choices. Gray buttons navigate; blue buttons revive a game or notify players, green buttons add a game or enable notifications, and red buttons turn notifications off. Back keeps the catalogue filter, search and page. Home returns to the private starting menu, also available with `/nexus`. Forms explain their fields and what submitting will do; closing a form leaves the previous menu in place. Submitting from a private menu updates that menu rather than adding another reply.

After rebuilding the image, stop the bot and rerun `docker compose run --rm bot node dist/cli.js setup`, then `docker compose up -d`. Setup converts the existing panel message to V2 without a duplicate or another import. Discord makes this message conversion permanent; future edits and panel moves retain V2. Old public buttons remain compatible during the transition.

1. Copy `.env.example` to `.env` and supply the existing Discord bot token, guild ID and RAWG key. Protect it with `chmod 600 .env`.
2. Enable **Server Members Intent** in Discord’s Developer Portal. Place the bot’s role above game roles. Grant channel/role management, history, attachments/embeds, thread management, and role mention permissions. Onboarding edits also require server management. Message content intent is unnecessary.
3. Build with `docker compose build --pull`, then run `docker compose run --rm bot node dist/cli.js doctor` for a read-only check.
4. Import existing games using a reviewed manifest and plan. See [migration instructions](migration.md); existing channels are never adopted automatically.
5. Explicitly install the panel with `docker compose run --rm bot node dist/cli.js setup`, then `docker compose up -d`.

Since 1.0.1, administrators use one Components V2 hub with **Requests**, **Catalogue**, **Maintenance** and **Panels**. The persistent staff button, Administration in personal menus and `/nexus-admin` (with no subcommands) open the same private hub. Requests support approval, rejection, clarification and linking to an existing game, including image uploads in a modal. Catalogue actions cover addition, editing, optional Discord name alignment, archiving, revival, suspension, retirement and guided repair using native channel/role selectors.

`/nexus-status` is an admin-only private shortcut showing recorded catalogue counts, open requests, unresolved operations and the last successful reconciliation. It does not start a diagnostic or reconciliation. Admin home opens the full panel.

Opening pages does not mutate Discord. Diagnostics and reconciliation previews are read-only; reconciliation and inactivity rotation require separate explicit confirmations. The Admin role bypasses member creation, revival, proposal and search quotas in both admin and member menus, including existing counters and the fifty-open-request anti-abuse threshold. Resource capacity, provider-wide RAWG quotas and permission checks still apply. Retirement preserves channels, messages, roles and subscribers.

Approval preparation shows whether the name/link and image are ready, with the next step and an explanation when review is unavailable. Open requests expire after thirty days without an update; clarification and member amendments restart that period. Closed requests remain visible for thirty days after approval, rejection or expiry, then are deleted. Audit entries and completed/failed operations are retained for thirty days; pending operations and those needing repair remain until resolved. Legacy records without update/closure dates receive a thirty-day grace period from the first cleanup after deployment. Cleanup runs at startup and before each periodic reconciliation. Catalogue data, images, subscriptions, import receipts, Discord messages and existing backups are preserved. Admin requests have no count cap within that retention window.

**Check now** immediately shows that a diagnostic is running, including any wait for reconciliation, followed by resource loading and the number of games checked. Back and Admin home remain available. Leaving the page stops further scanning after the current network request; late results or errors cannot replace a newer menu. Separate private messages remain independent. Completion and failures are shown explicitly, with a retry available after a failure.

Run `setup` once after upgrading to replace the twelve old subcommands and install/update both entry messages. It publishes the staff entry in an already private channel without overwriting its permissions; `--admin-channel ID` selects a different channel. If privacy verification fails, staff publication is refused, and admins can use the private hub to choose a suitable channel under **Panels**. No new import is needed. Migration `002` automatically preserves known game addition dates when the updated image opens the database; existing migration checksums remain unchanged. See the [administration guide](administration.md) for the deployment sequence.

After generating the inventory, run `pnpm admin prepare --inventory data/inventory.json --output data/import-preparation.json --rawg --locale en`. Open `data/import-preparation.html`, review the proposed matches, and download the confirmed manifest. No JSON needs to be written by hand. Preparation only examines the two specified game categories. The standby category keeps its ID and becomes the first hidden archive; up to two more archives are created as needed. This preparation does not modify Discord. Stop any previous rotation automation before applying the import.

Notification roles are listed alphabetically. If a role is missing, choose **Create a role for this game**, with a RAWG image or an existing parent role icon. The plan verifies the image and capacity before any Discord changes. Applying it creates the role with zero global permissions and no initial subscribers, preserving the existing channel and history.

Members with the configured Syndiqué role can create or revive one game per rolling 24 hours. New or revived games need a first human message within 48 hours. Established games archive after 30 days, preserving the fifteen most recently active established games. Catalogue: 150 games; archives: up to three hidden categories. Voice channels and events are outside V1.

Subscribing does not revive a game. Creating or reviving never subscribes anyone automatically. Successful new creations announce the game in the configured announcements channel, mentioning only the optional new game alerts role. Revivals and historical imports do not announce anything. Members can mention game notification roles directly in conversations. The private game card’s optional **Notify players** action remains available; arbitrary mentions inside its text are suppressed. Its cooldown applies only to that action, not to manual mentions.

**Recently added** opens a private list sorted newest first, with a five-game preview and relative dates, twenty games per page, search and Back preserving your place. Other catalogue filters stay alphabetical. Revival never changes an addition date. Known successful creation dates are recovered from the existing journal; undated historical games remain in **All**, without retroactive announcements.

**New game alerts** opens a private setting showing your actual Discord role membership, with an action to turn alerts on or off. It reuses **Nouveau Jeu** (`NEW_GAME_ROLE_ID`, default `1450484079228227674`). Announcements go to **🔎suggestions-de-greves** (`NEW_GAME_CHANNEL_ID`, default `389733957890998294`). The bot must be able to assign the existing unprivileged role and send messages in that channel. Manual role removals are respected, and this setting does not affect channel visibility or game subscriptions. Discord notification preferences still apply.

An announcement failure does not fail a successful game creation. Uncertain or interrupted sends are flagged to staff and never resent automatically. Confirmed delivery records expire after thirty days; unresolved records are retained. No diagnostic publishes announcements, and no historical catalogue is announced during deployment.

For an existing import made with non-mentionable roles, stop the bot and run `docker compose run --rm bot node dist/cli.js role-mentions --apply`, then restart it. This changes only existing catalogue roles, preserving subscriptions and channels. Without `--apply`, the command previews the changes. It checks all roles before updating any and can be rerun after interruption. `doctor` reports any remaining non-mentionable game roles in `unmentionableImportedRoles`. Normal reconciliation still respects manual Discord changes.

Discord wins during reconciliation. Manual channel moves, deleted resources and changed role holders are observed. Ambiguous partial operations require explicit administrator repair. No automatic channel deletion or history merging occurs.

Service logs use Pino: `LOG_FORMAT=json` by default, or `LOG_FORMAT=pretty` for readable Docker logs. `LOG_LEVEL=debug` includes interaction acknowledgement timing. Errors retain Discord codes, processing phases and safe source locations without tokens, request bodies or member text. Expired personal menus offer a Home button. Failed interaction acknowledgements are never retried with a second callback.

Reconciliation applies only subscriber differences in one SQLite transaction and yields to I/O between games. Unchanged subscriptions cause no writes. `reconciliation_started` and `reconciled.elapsedMs` show progress; `event_loop_blocked` reports an event-loop delay of at least one second. Interaction logs distinguish age on receipt (`receivedAgeMs`) from local processing time (`elapsedMs`) and include Gateway latency when known. Calculated interaction age also depends on host clock accuracy.

To update an existing public panel with new buttons, stop the bot, run `docker compose run --rm bot node dist/cli.js setup`, then restart. Setup edits the existing panel message in its current channel. `doctor` exposes catalogue counts under `catalogue.active`, `catalogue.archived` and `catalogue.unavailable`.

To audit tracked and untracked resources against the production database, run `docker compose run --rm bot node dist/cli.js audit --output /data/resource-audit.json`. Read `data/resource-audit.md` or its JSON counterpart on the host. It checks ordinary roles below the configured Games marker and textual channels in active/archive categories, using resource IDs rather than names. Retired entries and unfinished operations are separate from strictly untracked resources. Counts, known permission/onboarding references, missing resources, naming suggestions and name conflicts support later review or a renaming script. Subscriber IDs are not exported. Override the default marker with `--role-marker ID`, categories with `--categories ID,ID`, and report language with `--locale en`. The audit can run alongside the bot; incomplete snapshots, an empty database or a changing catalogue prevent a misleading clean report. It does not rename or remove anything.

Deployment is manual: pull the private repository, make a SQLite backup, then `docker compose up -d --build`. Back up the named volume using the CLI’s online SQLite backup command. Never remove the volume with `down -v`. See the [main guide](../README.md) for restoration and administration.

[RAWG Free](https://rawg.io/apidocs) allows personal noncommercial use and requires attribution links, which Nexus displays. Nexus caps its own requests at 18,000 per UTC month and has no paid fallback or Twitch connection. GitHub workflows use your account’s included Actions allowance; keep paid budgets at zero for strict free-tier use.

Member inventories and staff-channel privacy checks use fresh REST pagination, allowing previews and confirmations to follow one another within Discord limits. Gateway rate-limit failures retain their type, opcode and retry delay in logs, with a localized retry message in member and admin menus. Request payloads and member searches remain private.
